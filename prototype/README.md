# ERP-Agent 前端（传统 ERP + AI 智能体）

这个项目里现在有**两套入口，共用一套数据库和权限**：

- **传统 ERP**：销售订单、库存台账、出货管理、发票管理——表单开单、审核、出货、开票，和常见 ERP 的操作方式一致；
- **智能体**：在同一个系统里用自然语言查数、开单、看审批、回放审计。

页面不是静态原型：所有客户、库存、单据、审批与审计记录都来自 `erp/` 里的迷你 ERP（SQLite），操作会真正落库。

## 启动

直接双击 `index.html` 即可完整演示，不需要任何服务：

- 数据来自 `demo-data.js`，所有修改保存在浏览器 localStorage，刷新后仍在；
- 新增 / 修改 / 删除 / 审核 / 出货 / 开票 / 主数据维护 / AI 对话全部可用；
- 顶部黄色条提供「重置演示数据」。

可选：启动本地服务切到 SQLite 持久化模式（`python erp/server.py`，访问 `http://127.0.0.1:8765/`），接口行为与离线模式一致。

## 5 分钟演示路径

**传统 ERP 路径**
1. 左侧「销售订单」→ 新建订单：选客户、商品、数量，提交；
2. 如果金额 ≤ 5 万 → 直接「已审核」；> 5 万 → 进入「待审核」，切李明去审批中心通过；
3. 订单详情 → 登记出货 → 状态变「已出货」，库存台账的现存量、锁定量同步变化；
4. 切陈静 → 发票管理 → 开具发票 → 订单变「已开票」。

**AI 路径**
1. 工作台自动问“华东精密还有多少应收”，金额来自 SQL 聚合；
2. 输入“给华东精密开一张货单，A12 200 件，单价 85” → 草案 → 确认 → 生成 `SO-…`；
3. 输入“把华南区客户 C2088 的订单导出来” → `E_PERM_001` 红卡；
4. 审计页点任意 trace，看意图、草案、风控、确认、落单、锁库存的真实事件与哈希链。

两条路径写的是同一批表，所以在传统页面开的单，AI 能查；AI 开的单，传统页面能审核、出货、开票。

## 设计说明

- **两套入口、一套数据**：传统表单和 AI 对话走同一套校验与落库逻辑，不存在“AI 特批通道”；
- **身份可见**：顶部身份条展示当前员工、区域范围与会话时间；
- **风险可见**：草案内置校验清单与规则编号，确认弹窗强制勾选；
- **证据可见**：每个回答带 trace，审计页用时间轴 + 哈希链还原；
- **拒绝说人话**：拦截卡给出错误码、原因与下一步。
